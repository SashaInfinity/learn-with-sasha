## Refinement of the Learn With Sasha landing hero

### Critical finding (what the plan rests on)

The repo's existing "3D redesign" plan (`docs/superpowers/plans/2026-07-28-…`) has commits in the log, but **the source was never actually rewritten**. Verified facts:

- `SashaStage.tsx` is the _original_ 370-line monolith (raw `GLTFLoader`, hardcoded center-screen NDC anchor, `HERO_SCALE_FACTOR`/`HERO_Y_OFFSET`). It does **not** import anything from `src/stage/`.
- `src/stage/*`, `RocketLaunch.tsx`, `SashaFallback.tsx`, `useSashaAnchor.ts`, the Draco model, the decoder, the build script and the tests all exist on disk but are **dead code** — nothing imports them.
- LandingPage / AuthScreen / ChatHome do **not** register anchors; they use the old full-screen layout.
- `index.html` never got the preload hint.

So the pasted refinement plan is critiquing the real current state. We will **wire up the already-built, already-tested anchor system** (which fixes the root cause: center-screen NDC anchoring that makes the character collide with the headline) and **then** apply the visual refinements (nav, 3-column hero, reframed character, benefits section, curved divider).

The GLB is authored as 3 separately-scaled stacked discs (Body y:0→0.34, Head y:0.35→0.55, Hand y:0.25→0.67 at scale 5 vs 9.88). The "disassembled head" critique is real geometry, but per the hard rule in commit `15e26e4` we fix it with **camera/framing/grounding only** — never touching child-node transforms.

All your decisions confirmed: camera+grounding fix; header on landing+auth (not dashboard); nav links anchor-scroll to real landing sections.

### Phase B — The visual refinements from the pasted plan

**B1. New `src/components/SiteHeader.tsx`** — a marketing nav rendered on landing + auth only. Logo + "Learn With **Sasha**" wordmark + "AI Tutor" chip on the left; center links **How It Works · Topics · About** (anchor `<a href="#how">` etc., smooth-scroll via `scroll-behavior: smooth` on `html`); right side secondary **Log In** + primary gradient **Get Started →**. Mobile: collapses to logo + Get Started (links move into the page body). Uses `.lws-header` positioning pattern but as its own class (`.lws-site-header`) so the dashboard's authenticated header is untouched. Props: `{ onGetStarted: () => void; onLogin?: () => void; variant: 'landing' | 'auth' }`.

**B2. `src/components/AppShell.tsx`** — wrap the landing and auth branches in a shared column layout that renders `<SiteHeader>` above the screen:

```tsx
if (showLanding) return <div className="lws-marketing-shell">{stage}<SiteHeader variant="landing" onGetStarted={...} /><LandingPage .../></div>;
if (!user)        return <div className="lws-marketing-shell">{stage}<SiteHeader variant="auth" onLogin={...} /><AuthScreen/></div>;
```

Dashboard branch unchanged. The landing/auth containers get `padding-top: var(--lws-header-h)` so content clears the fixed header.

**B3. `src/components/LandingPage.tsx`** — full rewrite merging Task 12 with the pasted plan's content hierarchy. Registers an anchor via `useSashaAnchor(ref, 'landing', { fillY: 0.92, max: 1.7 })`. Structure:

- **Left column** (defined `1fr`, right-aligned text): eyebrow `AI MATH TUTOR`, a refined brand mark (see B5), 2-line headline `Learn` / `<amber>With Sasha</amber>` (slightly smaller, `clamp(32px,5.4vw,54px)`), one-line sub `Personalized math learning that feels like having a tutor beside you.`
- **Center column** (`auto`, the anchor div): Sasha. `gap` of `--lws-space-6` between columns so the headline clears the character.
- **Right column** (`1fr`, left-aligned): short value prop `Your personal AI math tutor, available whenever you need help.`, **3 benefit rows** with icons (`BookOpenIcon` Explore concepts your way · `CalculatorIcon` Solve problems step by step · `SpeakerIcon` Learn with Sasha's voice), CTA `Get Started →` (`.lws-cta .lws-lift` with arrow glyph), reassurance `Personalized lessons · Progress saved automatically`.

Keep the existing `wave` mood + delayed `speak()` greeting logic.

**B4. Reframe the character (B3's "composition fix")** — done purely through the anchor's fit options and the camera director, no model edits:

- In `LandingPage`'s anchor opts: `fillY: 0.92, fillX: 0.8, max: 1.7` so the whole figure (including head) fits inside the anchor box with breathing room, eliminating the top-of-head crop.
- The anchor box itself sits in a centered grid column with explicit height `clamp(360px, 56vh, 560px)` on desktop, so the figure is grounded within a known frame rather than floating against the viewport edge.
- Strengthen the ground halo in `renderer.ts`: raise the ground-disc opacity floor from `0.05` to a soft `0.10`–`0.14` elliptical shadow (swap `CircleGeometry` for a slightly squashed/elliptical amber disc) so the stacked discs read as one **anchored** figure. This directly answers "feels anchored rather than floating."
- Camera `wide` shot already targets `y:0.6`; keep it. The framing is now driven by the anchor box, not a hardcoded NDC, so the head no longer collides with the viewport top.

The `∞` in AuthScreen's card and the dashboard header stay (they're a recognizable secondary mark there) — only the landing's disconnected one is replaced.

Add an `#topics` strip (sample math topics as chips) and a short `#about` paragraph + secondary CTA so all three nav anchors resolve.

- Hero background: soft off-white (`#f8fafc`, already the body bg).
- Lower section: slightly warmer panel (`#fffaf2` / amber-50 tint).
