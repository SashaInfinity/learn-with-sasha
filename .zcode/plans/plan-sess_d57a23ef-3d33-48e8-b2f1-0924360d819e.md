# Fix Login for Learn with Sasha (port the LMS auth flow)

## Root cause
The LMS auth integration is **already correctly implemented** in the Express backend (`server/src/lib/auth.ts`, `server/src/routes/auth.ts`) — it proxies login to the LMS FastAPI backend (`AUTH_BACKEND_URL/auth/login`), stores the returned JWT in an httpOnly cookie, and validates sessions via `/auth/me`. The frontend (`AuthContext.tsx`, `api.ts`, `AuthScreen.tsx`) is correctly wired to use it.

The **actual bug is the dev wiring**: `vite.config.ts` has **no `server.proxy`**, while `api.ts` uses `BASE = ''` (same-origin). So in local `npm run dev`, `POST /auth/login` hits the Vite dev server (port 3000) and returns SPA HTML instead of reaching the Express backend (port 3002) → login silently fails. In prod it only works because nginx/Apache does this proxying. Additionally, the committed `server/.env` is set to `NODE_ENV=production` + `COOKIE_DOMAIN=learn.sashainfinity.com`, which would break local cookie-setting, and `AUTH_BACKEND_URL` points at a local FastAPI that isn't running.

## Approach
Since you want login to **point at the remote LMS** and work in **both dev and prod**, the plan is:

1. **Add the missing Vite dev proxy** so same-origin `/auth` and `/api` requests from the dev server (port 3000) reach the Express backend (port 3002). This mirrors what nginx does in prod.
2. **Make the auth-backend target configurable and default it to the remote LMS** (`https://backend.sashainfinity.com/api/v1`) so login works without running the local FastAPI/Postgres stack.
3. **Fix the dev environment config** so cookies set correctly on localhost (a dev-oriented env with `NODE_ENV=development`, no `COOKIE_DOMAIN`, localhost CORS).
4. **Document the prod proxy requirements** so the same fix is unambiguous in production.

## Changes

### 1. `vite.config.ts` — add dev proxy (the core fix)
Add a `server.proxy` block that forwards `/auth` and `/api` to the Express backend at `http://localhost:3002` (configurable via `VITE_BACKEND_URL`/`VITE_PROXY_TARGET`). Use `changeOrigin: true` so the cookie domain matches, matching the existing same-origin + `credentials: 'include'` design in `api.ts`. Keep all existing config (port 3000, `define` security stubs, `resolve.alias`, build chunks) intact.

### 2. `server/src/lib/config.ts` — default auth backend to remote LMS
Change `AUTH_BACKEND_URL` from **required** to **optional with a default** of `https://backend.sashainfinity.com/api/v1` (the production LMS API, confirmed from the LMS `docker-compose.yml`). This lets login work out of the box without the local FastAPI running, while still allowing `AUTH_BACKEND_URL` to override it (e.g. back to `http://127.0.0.1:8000/api/v1` for local LMS development).

### 3. New `server/.env.development` + update `server/.env.example`
- Create a dev env template (`server/.env.development`) with `NODE_ENV=development`, `CORS_ORIGIN=http://localhost:3000`, `AUTH_BACKEND_URL=https://backend.sashainfinity.com/api/v1`, **no `COOKIE_DOMAIN`** (so the cookie takes the localhost host), and placeholders for `DATABASE_URL` / `GEMINI_API_KEY`.
- Leave the existing prod `.env` untouched (it's gitignored and correct for production).
- Add a note in `.env.example` clarifying the dev vs prod values.

### 4. `docs/` — short "Auth & login" runbook
Add a concise doc (`docs/AUTH_LOGIN.md`) explaining: the LMS-backed auth flow, how to run the backend + frontend together, the required dev proxy, the prod nginx/Apache reverse-proxy rules for `/auth` and `/api`, and how to switch the auth backend between local-FastAPI and remote-LMS.

## What I will NOT change (already correct)
- `src/lib/api.ts` — the fetch client with `credentials: 'include'` and `/auth/login` → `/auth/me` → `/auth/logout` is correct.
- `src/context/AuthContext.tsx` — login/logout/session-restore logic is correct.
- `src/components/AuthScreen.tsx` — the form + submit handler is correct.
- `server/src/lib/auth.ts` & `server/src/routes/auth.ts` — the LMS proxy (login → cookie, /me validate, logout) is correct and matches the LMS `TokenResponse`/`UserResponse` shapes.
